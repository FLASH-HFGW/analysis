# IQ autoreconstruction v3.1 — official code and product semantics

This document describes the released IQ reconstruction implementation and its archived validation evidence. It does **not** modify production settings or authorize a new deployment. See [the ROOT v3.1 format reference](iq_root_v31.md), [the operational runbook](run3_root31_runbook.md) and [the documentation policy](DOCUMENTATION_POLICY.md).

## Architecture

The MIDAS reader validates Begin-of-Run (BOR) settings, then consumes successive digitizer events without retaining complete waveforms. The worker produces an intermediate HDF5 representation, serializes the ROOT v3.1 format, verifies data integrity, and publishes the product using the existing controlled storage and job flow. Existing destinations are not silently overwritten.

The implementation includes `examples/analyze_midas_iq_v3.py`, `examples/iq_compact_spectra.py`, `examples/iq_midas_aux.py`, `examples/iq_root.py`, `examples/iq_root_worker.py`, `examples/iq_thermometers.py` and the `autoreco/` orchestration modules.

The native ROOT file includes all verified derived IQ statistics and PSD data, run timing metadata, BOR/EOR ODB snapshots, slow-control records and auxiliary MIDAS bank provenance. Complete raw ADC waveforms are excluded.

## Channel and ADC conventions

Physical ADC channels use signed `int16`, scaled using the peak ADC range from BOR: `2 × peak_range_V / 65535`. The complex mode convention is `z = I − i Qhardware`. The mode-to-channel mapping must come from verified run metadata or an explicit configured mapping. The historical SPEC and newer SPE layouts must not be assumed interchangeable. For the validated selection the mode pairs are TM010 (0,1), TM011 (2,3), TM012 (4,5).

The physical received-sample clock comes from BOR (nominally 5 MS/s). Missing/invalid digitizer serials terminate a contiguous segment. Sample-based acquisition timing must not be presented as independently PPS-to-UTC-calibrated timing.

## Spectra and statistics

The standard compact profile stores:
- `spectra/<mode>/mean_psd`: arithmetic mean of one-second complete-window PSDs, in V²/Hz
- `spectra/<mode>/window_psd`: ordered one-second PSDs, normally 209 × 50,000 for 209 complete windows at 100 Hz resolution
- `spectra/window_bin_edges_hz` and `spectra/window_bin_width_hz`: signed frequency coordinates and exact widths
- `short_psd`: temporally averaged rectangular/Hann 16,384-sample FFT powers; per-short-FFT chronology is not stored
- `statistics`, `histograms`, `anomalies` and `quality`: full-run moments, diagnostic populations and data-integrity evidence.

The compact spectrum is generated by averaging powers, not amplitudes. Summed PSD × bin width agrees with mean complex-signal power to the validated numerical precision. Complete one-second windows contribute to the PSD, while valid residual samples are included in full-run time-domain moments. Avoid mixing these populations.

Optional payload switches for explicitly requested diagnostics include `--product psd` or `--product fft` (full one-second spectra), `--max-psd`, `--band LOW_HZ HIGH_HZ`, `--band-product` and `--compression`. Full spectra are much larger than compact products.

## Validation and historical observations

Previous validated work examined legacy Run 680 and Run3 Runs 1145/1148/1422. A full Run 680 legacy example had 1,048,576,000 received complex samples/mode, 209 complete one-second windows and 3,576,000 residual samples. The ROOT round-trip audit for Run 1422 verified all 43 pre-existing HDF5 datasets and 67 total datasets. The ROOT file was 156,901,974 bytes (Adler32 `721868e3`) and its worker test ended successfully. See `docs/iq_root_v31.md` for the detailed receipt and limitations.

Timing diagnostics identified an incomplete SPGP PPS pair in Run 1148 and discrepancies in mapping TGPS text timestamps onto ADC PPS events. Such limitations remain explicitly represented in the products rather than being silently repaired.

## Branching and operating policy

`main` is the official source-code baseline for the already operational ROOT v3.1 autoreconstruction. Experimental analysis and proposed reconstruction changes should be developed separately and integrated only after review. Local `config/autoreco_run3.json`, worker credentials, Condor state, runtime validation receipts and job queues must not be overwritten by a source-control update. The tracked `config/autoreco_run3.example.json` is a **disabled template**. The actual `config/autoreco_run3.json` is excluded from version control, must be managed on PSGE, and must not be replaced by this merge.

Never assume that merging a source branch, updating a checkout, submitting HTCondor jobs or re-enabling cron are equivalent operations. Production deployment and live job actions require a distinct operational check.
